# C - Number Place

## 問題概要

1〜9の整数で埋まった9行9列の盤面を、各行9整数として読む。全ての行、列、縦横3マスずつの非重複ブロックに、1〜9がそれぞれちょうど1回現れるかを `Yes` / `No` で答える。

## 解法の概要

各マス群について、値を添字とした使用済みフラグを初期化し、同じ値が2回現れた時点で `No` とする。各群には範囲1〜9の値が9個あるため、重複がなければ9種類が1回ずつ現れる。固定9×9のため時間・メモリは O(1)。同じ構造で一辺の長さを `D` とすれば、時間 O(D²)、盤面 O(D²)、一度に走査する群のフラグ O(D)。

主分類は [グリッド](../../分野/グリッド/グリッド.md)。

## 問題固有の実装ポイント

- 値から1を引くと、長さ9のフラグ配列で添字0〜8として扱える。値域の保証が必要。
- 同じ `i` の行 `a[i][j]` と列 `a[j][i]` は同じループで走査できるが、フラグは群ごとに独立させる。
- ブロック番号 `box` を0〜8とすると左上は `((box/3)*3, (box%3)*3)`。各ブロックでフラグを初期化する。隣接する3×3窓をすべて調べる処理とは走査範囲が異なる。

## 自作コード

Inbox で照合した C++ のローカルスナップショット（取得元 `atc-rs-local`）を参照した。提出との対応とジャッジ結果は未確認。

盤面は `vector<vector<int>>` に0〜8として格納し、行・列は `didc` と `didr`、3×3ブロックは `did` の `vector<bool>` で重複を確認する。検出時に即終了し、全27群を通過したら `Yes`。`LOCAL` を定義しない場合は `debug` が空操作になる。固定の27群の走査と重複検査はこの問題ノートで参照できる。

検証では `LOCAL` なしでC++20としてコンパイルし、全3サンプルと、正しい盤面全体の数字の置換・1マスの変更を含む60盤面を集合ベースの判定と照合した。
